# Handoff — следующий шаг: этап 6, DNS

Ближайшая цель — заменить `servfailResolver` настоящим перехваченным DNS из
§5.7. Регистр уже написан в `docs/verification-dns.md`; реализовывать в порядке
его §7, начиная с L1 без сети и Xray:

1. разбор DNS-сообщения и сборка ответа — D2–D8, D14, D15;
2. один UDP-апстрим, таймаут и общий бюджет — D1, D40, D44;
3. второй апстрим с форой 150 мс — D41–D43;
4. повтор по TCP при TC и усечение ответа клиенту — D33–D37;
5. TTL/negative cache, LRU и single-flight — D21–D32, D38, D39;
6. фазы `waiting`/`failing`/`bypass` и проводка в `internal/agent` — D9–D13,
   D17, D20;
7. события health, AAAA/ECS, затем bootstrap и L2 — оставшиеся D* и T14/T16.

Критическое ограничение §6.8: bootstrap не имеет права использовать
`http.DefaultTransport` или голый `net.Dialer`. Его TCP/UDP-сокеты должны брать
текущий физический интерфейс через `internal/outbound.Selector` и отказывать,
если интерфейс не определён. Основной DNS, напротив, идёт через outbound
активного узла.

Гейт завершения этапа: `go test ./...`, `go test -race` для новых DNS-пакетов и
L2 T14/T16. Каждая новая политика из регистра обязана иметь краснеющую проверку
через `negcheck`.
