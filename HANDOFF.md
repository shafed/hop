# Handoff — этап С доведён до рабочего hop up, §6.8 ждёт реализации

Дата: 2026-08-22. Ветка `claude/pass0-decisions-registry`, всё
**незакоммичено**.

---

## 1. С чего начался заход

Жалоба: «мои рабочие конфиги пингуются и работают через другие приложения,
однако трафик не идёт через proxy».

Диагноз оказался двухслойным, и оба слоя настоящие.

**Слой первый — датаплейна не было вовсе.** `cmd/hop` оставался заглушкой этапа
2 и после коммита `d9937b0`, который написал связку: тот коммит добавил 3064
строки в `internal/agent` и **ни одной** в `cmd/hop`. Собранный `hop` не
содержал ни одного символа Xray, netstack, `agent` или `store` (проверяется
`go tool nm`). Датаплейном был `drain`, читавший TUN и выбрасывавший
прочитанное, при том что `hopd` заворачивал в туннель весь трафик машины. То
есть `hop up` означал не «мимо прокси», а чёрную дыру.

**Слой второй — правило §6.8 выводило мимо туннеля весь трафик пользователя.**
Оно выражено `ip rule add uidrange <uid>-<uid> lookup main priority 31500` и
верно ровно тогда, когда агент работает под отдельным системным пользователем.
Здесь он работает под пользователем рабочего стола, поэтому мимо туннеля уходило
всё, что человек запускает. До этого захода поле `AgentUID` уходило нулём, и
дефект был не виден: правило защищало root.

| `device_windows.go` | громкий отказ: там устройство приезжает трубой, это этап 8                       |
| `prober.go`         | `MultiProber` на трёх URL §5.4 через outbound узла (§6.7)                        |
| `store.go`          | корень стора `~/.config/hop`, 0700 (Р37)                                         |

Плюс `Agent.ProbeDial` (`internal/agent/dialer.go`) и метка пробы
`engine.WithProbe` (`internal/engine/dialer.go`, Р38).

**Живое подтверждение.** При поднятом туннеле, под root: непривязанный сокет
уходит с `10.255.0.1`, соединение до внешнего адреса устанавливается. Датаплейн
работает сквозняком: netstack → диалер → Xray → узел.

### Реестр проверок

`docs/verification-agent.md` §5.8 — W36–W46. Все зелёные. Каждая новая проверка
проверена на **красноту**: починка откатывалась, падение фиксировалось.

### Три дефекта, найденных и закрытых по дороге

1. **`AgentUID` уходил нулём** — правило §6.8 защищало root вместо агента (W36).
2. **Проба засчитывалась дважды** — и в окно проб, и в счётчик ошибок трафика,
   вопреки §5.4. Решение Р38: контекст пробы помечается, `nodeDialer` молчит.
   Отменяется рассылка, а не классификация (W37).
3. **Гонка закрытия дескриптора** — `close` выдёргивал fd из-под спящего
   читателя, `EBADF` вместо `io.EOF`. Решение: будилка + `RWMutex` (W44).
4. **Туннель оставался поднятым при отказе записи токена** — нашёл Codex. `Stop`
   не звался, получалась та же чёрная дыра (W45, W46).

## 3. Что делать дальше — §6.8, привязка вместо uid-правила

**Решение принято и обосновано замером.** §6.8 в `SPEC.md` уже переписан,
обоснование — в `implementation-notes.md`, раздел «§6.8 переписан по замеру».
Осталась реализация.

### Замеры, на которых стоит решение

Под uid 1000, без capabilities, ядро 7.1.5 (сделано дважды, независимо):

| операция                              | результат                 |
| ------------------------------------- | ------------------------- |
| `SO_MARK`                             | `EPERM` — fwmark отпадает |
| `SO_BINDTODEVICE`, свежий сокет       | работает                  |
| `SO_BINDTODEVICE`, повторно / отвязка | `EPERM`                   |

При поднятом туннеле:

```
uid 1000: без привязки → 192.168.0.125   с привязкой → 192.168.0.125
uid 0   : без привязки → 10.255.0.1      с привязкой → 192.168.0.125
```

Программа замера: `scratchpad/bindcheck/` (вне репозитория). Стоит перенести в
репозиторий как проверку — сейчас она времянка.

### Что менять

**`internal/platform/linux.go`**

- убрать шаг `"loop guard uid …"` (~строки 169–180) и константу `prioLoopGuard`;
- из `Reclaim()` `prioLoopGuard` **не убирать сразу**: одна версия должна ещё
  уметь подобрать правило, оставшееся от предыдущей сборки. Иначе после
  обновления у людей останется висящее правило, выводящее весь их трафик мимо
  туннеля;
- `prioExclusions` (31000) и `prioTunnel` (32000) не трогать.

**`internal/engine/dialer.go`** — точка вставки уже есть: `nodeDialer.Dial`
получает `sockopt *internet.SocketConfig`. Проставлять `sockopt.Interface`
(создавая `SocketConfig`, если пришёл `nil`). Дальше Xray сам разложит это в
`SO_BINDTODEVICE` / `IP_BOUND_IF` / `IP_UNICAST_IF` — три ОС закрываются одним
полем, кода привязки писать не нужно.

**Определение интерфейса** — искать дефолтный маршрут в таблице `main`,
отбрасывая маршруты с `LinkIndex == tunIndex`. Образец:
`refs/Xray-core/proxy/tun/tun_linux.go:364` (MPL, читать и заимствовать можно).
Отслеживание — подписка на rtnetlink; под uid 1000 работает.

**Если интерфейс не определён — отказывать в дозвоне**, а не выпускать
непривязанный сокет: непривязанный сокет в этот момент и есть петля, молчаливая,
а §5.6 против молчания.

**Щель, которую надо закрыть явно.** Привязка накрывает только те сокеты, на
которых поставлена. Резолвер bootstrap (§5.7) и скачивание подписок (§5.8) ходят
мимо Xray и требуют своего `net.Dialer{Control: …}`.

**Задеваемые файлы:** `internal/tunnel/tunnel.go:70` (`AgentUID` становится не
нужен), `cmd/hop/main.go` (`tunnelParams`), `internal/ipc/server.go:83`,
`internal/ipc/secret_test.go`, `cmd/hop/transport_test.go` (`TestW36` заменяется
проверкой новой защиты).

## 4. Открытое, не закрытое

- **Разрыв соединений при смерти узла (§5.5)** не выполняется:
  `health.Config.Interrupt` пуст, у netstack нет реестра живых потоков. W8 и W14
  в реестре красные. Закрывается вместе с этапом 8.
- **`hop0` переживает teardown**, если гасить `hopd` при живом агенте: интерфейс
  уходит с последним дескриптором. Правильный порядок — сначала `hop`, потом
  `hopd`. Считать ли это дефектом §8.4 — не решено.
- **Пустая группа остаётся в сторе** после `-rm` по id группы: удаления группы
  целиком стор не умеет. Косметика, этап 9.
- **`TestT10SlowNodeKeepsConnectionAlive`** (`internal/l2`) — плавающая под
  нагрузкой. Упала один раз в полном прогоне, не воспроизвелась ни на чистом
  HEAD (8 прогонов), ни на рабочем дереве (8 прогонов). Приписать правкам не
  удалось; направление эффекта Р38 противоположное.
- **Нижняя граница по версии ядра** для непривилегированной `SO_BINDTODEVICE` не
  установлена.
- **Флаги `-sub`/`-node`/`-rm`/`-probe`** — временные, снимаются этапом 9 вместе
  с подкомандами. Записано в `PLAN.md`.

## 5. Как это запускать

v2raya обязан быть **выключен**: его правило перехватывает исходящее соединение
агента к узлу, и REALITY получает подлинный сертификат вместо поддельного. Это
стоило одного неверного диагноза — «узел не работает», — который на деле означал
«до узла не дают дойти».

```
sudo systemctl stop v2raya
./hop -sub 'ссылка'        # или ./hop -node 'vless://…'
./hop -probe               # проверка узлов без туннеля и без root
sudo ./hopd -group users -debug    # в отдельном окне
./hop -debug                       # в другом
```

Пользователь не состоит в группе `hop`, поэтому `-group users`. Останавливать в
обратном порядке: сначала `hop`, потом `hopd`.
