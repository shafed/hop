# Handoff — следующий шаг: L2 для резолвера и хвост D34б

Этап 6 закрыт на уровне L1: `internal/resolver` отвечает на перехваченный :53
по-настоящему — два апстрима через активный узел с форой 150 мс, повтор по TCP
на флаг TC, кэш с TTL и отрицательный кэш, склейка одинаковых вопросов,
fail-close и удержание в стартовом окне, сброс кэша по подписке на события
живости, синтез пустого ответа на AAAA, вырезание ECS и bootstrap мимо туннеля.
Заглушки `servfailResolver` больше нет на пути продукта: связка собирает
настоящий резолвер, а имена узлов резолвятся до Xray, иначе §5.7(а) даёт петлю.

Ближайшая цель — шаг 10 регистра `docs/verification-dns.md` §7, то есть L2:

1. T16 перегнать против настоящего резолвера, а не против фейка `fakenet`;
2. T14 на настоящем узле: домен резолвится в IP1 через A и в IP2 через B,
   переключение — следующий резолв даёт IP2;
3. усечённый ответ через настоящий узел: апстрим за узлом отдаёт TC, резолвер
   обязан повторить по TCP и вернуть полный RRset.

Стенд L2 уже есть — `internal/l2/harness_test.go`: настоящий Xray, настоящие
VLESS-соединения через инжектор отказов, `internal/xraytest` поднимает инбаунд.
Апстрим-сервер поднимается **за** узлом, поддельный `PacketDevice` — из
`internal/packettest`.

Второй хвост, поменьше: строка **D34б**, заведённая по итогам реализации.
Усечённый ответ клиенту уходит без записи OPT. Ответ этот мы не пропускаем, а
сочиняем, и OPT в нём обязана отражать EDNS0 **клиента** (RFC 6891 §6.1.1);
`dnsmsg.Fit` запроса клиента не видит, поэтому чинить надо в резолвере, где на
руках и запрос, и ответ. Неверного ответа сейчас нет — TC уводит клиента на TCP
в любом случае, — но клиент с EDNS0 вправе счесть нас не понимающими EDNS0 и
опустить буфер до 512.

Гейт: `go test ./...`, `go test -race ./internal/resolver ./internal/netstack`,
`go run ./cmd/negcheck`. Каждая новая политика обязана иметь проверку, красную
без неё, — `negcheck` гоняет каждый охранник дважды и ловит обратное.
