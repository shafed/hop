# Ещё не написано

Единственный список исключений `cmd/doclint`. Линтер читает его сам: номер,
имя политики или путь, названный в документах, либо имеет исполнимое
подтверждение — Go-тест с этим номером, запись в `internal/policy`, файл на
диске, — либо стоит здесь строкой с причиной.

Список работает в обе стороны: строка, ставшая ненужной (тест написан,
политика зарегистрирована, файл появился), краснит линтер точно так же, как
утверждение без подтверждения. Свалкой он поэтому не станет.

Мёртвое имя, которое документ называет намеренно и которое никогда не станет
живым (разбор чужой ошибки, цитата несуществующего документа), можно погасить
двумя способами: словом `doclint:ignore` в той же строке — если строку вообще
позволено править, — либо строкой в разделе «Названы мёртвыми» ниже, если имя
стоит в замороженной записи прошлого прохода.

## Названы мёртвыми

Обратная сторона списка: эти имена названы в документах намеренно и обязаны
**не** существовать. Строка здесь гасит имя во всех документах сразу, поэтому
её ставят только тогда, когда пометить `doclint:ignore` конкретную строку
нельзя.

- `constraints.md` — документ, на который два прохода подряд сослались как на
  основание отложить задачу и которого никогда не было ни в одной ветке.
  Разбор — `implementation-notes.md`, «Довод об объёме, которым откладывали».
  Ссылку называет и `HANDOFF.json` в записи закрытого прохода, править которую
  этот проход не имеет права.
